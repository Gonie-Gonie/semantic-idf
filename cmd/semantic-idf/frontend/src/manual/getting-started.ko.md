# 시작과 기본 작업

SemanticIDF는 EnergyPlus 모델을 읽고, 편집 가능한 입력과 정적 분석을 제공하며, 시뮬레이션 결과를 해석합니다. 이 매뉴얼은 조작 방법과 표시된 수치의 해석을 함께 설명합니다. 모델의 정적 분석과 EnergyPlus 실행은 별개의 작업입니다.

## 매뉴얼 사용법 {#manual}

Settings, Guide, Tools는 앱 안의 보조 패널로 열립니다. 뒤의 Main은 현재 입력, 분석 결과, 시뮬레이션 결과, 선택 항목과 화면 위치를 유지합니다. 패널의 × 버튼이나 Escape 키로 닫으면 Main으로 돌아갑니다. 앱을 사용하는 동안 각 패널의 작업 상태도 유지되므로 저장 전 Settings 변경과 읽던 Guide 장을 이어서 볼 수 있습니다. 도움말이나 설정을 여는 동작으로 분석이나 EnergyPlus를 다시 실행하지 않습니다. Tools에서 Diagnose 수정을 적용하거나 다른 입력을 선택하면 Main의 입력과 분석이 갱신됩니다.

장 목록에서 기본 사용부터 기술적 해석까지 이동할 수 있습니다. 절 목록은 현재 장의 특정 주제로 이동합니다. 검색은 장 본문과 지표 카탈로그를 대상으로 하며, 결과를 선택하면 해당 장과 절을 엽니다. 장·절 URL을 저장하고 브라우저 뒤로/앞으로 이동을 사용할 수 있습니다.

매뉴얼은 설정에서 선택한 프로그램 언어를 따릅니다. 한국어는 한국어 본문을, 그 외 언어는 영어 본문을 사용합니다. 두 언어에서 절 ID를 공유하므로 프로그램 언어를 바꿔도 같은 주제를 유지합니다. Metrics, Profile, Energy Path, HVAC처럼 익숙한 기능명과 전문용어는 영어로 표기합니다.

| 작업 | 읽을 장 |
| --- | --- |
| 입력 열기·편집·저장 또는 원본 객체 찾기 | [입력과 원본 탐색](./input.ko.md) |
| 면적·외피·부하·스케줄 값 이해 | [지표와 Profile](./metrics.ko.md) |
| 3D·Plan·Network 모델 이해 | [공간·열 연결](./topology.ko.md) |
| 입력의 공기·물 계통 추적 | [HVAC 모델 해석](./hvac.ko.md) |
| EnergyPlus 실행과 시계열 결과 해석 | [시뮬레이션](./simulation.ko.md) |
| 부하 원인·공급 열량·소비 에너지 설명 | [에너지 경로](./energy-path.ko.md) |
| 여러 파일 비교·입력 정리·앱 설정 | [Tools와 설정](./tools.ko.md) |
| 내보내기 자동화·기존 SQL 읽기 | [CLI·API·내보내기](./automation.ko.md) |
| 단위·결측값·실행 실패 확인 | [단위·용어·문제 해결](./reference.ko.md) |

매뉴얼과 오프라인 지표 카탈로그는 실행 파일에 포함됩니다. 도움말을 읽는 데 인터넷 연결, EnergyPlus 설치 또는 실행 중인 시뮬레이션이 필요하지 않습니다. 일반 브라우저 미리보기에서도 데스크톱 API가 없으면 포함된 카탈로그를 사용합니다.

## 처음 사용하기 {#first-session}

1. CLI 명령 없이 실행 파일을 시작합니다.
2. 시작 시 reference Large Office 모델을 엽니다. 이 값은 내 프로젝트가 아닌 샘플의 결과입니다.
3. Open으로 원하는 입력 파일을 선택합니다.
4. 필요한 분석 단계가 끝날 때까지 기다립니다. Metrics와 입력 보기가 다른 분석보다 먼저 준비됩니다.
5. Metrics와 경고를 살펴보고 필요한 형상과 시스템 연결을 확인합니다.
6. 의도한 변경을 저장합니다. 시뮬레이션이 필요할 때 엔진과 기상 파일을 설정합니다.

파일 선택기는 .idf, .imf, .epjson, .json, .txt를 지원합니다. 확장자만으로 지원되는 EnergyPlus 모델임을 보장하지 않습니다. 입력의 Version과 파싱 결과로 내용을 해석합니다.

파일을 열면 자동 분석합니다. 구조화된 필드를 바꾸면 공유 문서와 분석을 갱신하며, 일반 흐름에 별도 Analyze 버튼은 없습니다. 아직 준비되지 않거나 실행 중인 결과를 계산된 0으로 읽으면 안 됩니다.

## 작업 공간 {#workspace}

왼쪽의 Text·JSON·Table은 하나의 편집 문서를 동기화해서 보여줍니다. 오른쪽은 Metrics·Topology·Profile·HVAC·Simulation 결과입니다. 구분선을 움직여 작업에 맞게 넓이를 조절하며 각 패널은 독립적으로 스크롤합니다.

Tools·Guide·Settings는 별도의 보조 페이지입니다. 기존 탐색 방식으로 앱에 돌아오면 작업 공간을 유지합니다. 보조 페이지 진입 자체는 EnergyPlus 재실행 요청이 아닙니다.

| 결과 | 답하는 질문 | 이 결과만으로 판단할 수 없는 것 |
| --- | --- | --- |
| Metrics | 입력에 명시되거나 계산 가능한 값은 무엇인가? | 실제 건물 성능 또는 엔진 실행 완료 |
| Topology | 공간 객체와 선언된 열 경계는 어떻게 연결되는가? | 가까운 객체 사이의 동적 열 흐름 |
| Profile | 원본·Zone별 부하와 스케줄 패턴은 어떻게 다른가? | 기상 기반 연간 시뮬레이션 |
| HVAC | 객체·Node·서비스가 어떤 시스템을 이루는가? | 명목 성능에서 추정한 실제 소비량 |
| Simulation | 이 실행과 출력에서 무엇을 관측했는가? | 편집한 현재 입력과 과거 결과의 일치 |

Metrics·Profile·Topology·입력 보기는 참여하는 원본 선택을 공유합니다. HVAC와 Simulation은 자체 선택 문맥을 유지합니다. 분석 패널에서 고른 Zone으로 복원된 시뮬레이션 결과의 범위를 덮어쓰지 않습니다.

## 모델 검토 순서 {#review-workflow}

새 모델을 검토할 때 다음 순서를 권장합니다.

1. 모델 식별 정보와 Version을 확인합니다.
2. Metrics에서 객체 구성·면적·상태를 확인합니다. 비율을 읽기 전에 예상 밖의 0과 결측값을 조사합니다.
3. Topology에서 대표 외부면·개구부·Zone 간 경계를 확인합니다.
4. Profile에서 대표 Zone의 부하 밀도와 스케줄을 비교합니다.
5. HVAC에서 대표 공급·환수와 Zone 서비스 경로를 추적합니다.
6. Diagnose에서 미해결 참조와 정리 후보를 검토합니다.
7. 검증된 기상 파일로 필요한 목적의 시뮬레이션을 실행합니다.
8. 연간 값 비교 전에 ERR 상태·출력 가용성·기간 범위·Energy Path 품질을 확인합니다.

예를 들어 면적당 에너지가 예상보다 작다면 분모 면적, Zone multiplier, 소비량 결측이 원인일 수 있습니다. 이를 곧바로 효율 개선으로 해석하지 말고 절대량·면적 기준·가용 범위를 함께 비교합니다.

## 저장·되돌리기·결과 식별 {#save-revert}

Save는 현재 편집 내용을 열린 파일에 씁니다. 원래 경로가 없으면 저장 위치를 요청합니다. Revert는 가장 최근 Open 당시 스냅샷을 복원하며, 여러 단계의 편집 실행 취소 이력과는 다릅니다.

탐색 뒤로/앞으로는 문서를 편집하는 대신 화면 상태를 복원합니다. 텍스트 편집의 실행 취소/다시 실행과 화면 이력은 구분됩니다. 객체 편집은 [입력](./input.ko.md), 실행 입력 보존은 [시뮬레이션](./simulation.ko.md)을 참고합니다.

시뮬레이션 출력 요청은 일반적으로 실행용 사본에 추가됩니다. 저장된 결과는 실행 입력·엔진·기상·실행 디렉터리에 속합니다. 나중에 편집기를 바꿔도 기존 관측값은 바뀌지 않으며, 과거 결과를 내보낼 때 현재 편집이 조용히 포함되지 않습니다.

## 키보드와 원본 탐색 {#keyboard}

기본 단축키이며 Settings에서 바꿀 수 있습니다. 단축키는 화면 문맥에 따라 동작하고, 편집기에서는 필요한 경우 일반 입력이 우선합니다.

| 동작 | 기본 키 |
| --- | --- |
| 열기 / 저장 | Ctrl+O / Ctrl+S |
| 화면 이력 뒤로 / 앞으로 | Alt+Left / Alt+Right |
| 명령 팔레트 | Ctrl+K |
| 다른 패널에 포커스 | F6 |
| 선택 원본 표시 | Ctrl+Shift+S |
| 정의 / 참조 | F12 / Shift+F12 |
| 현재 검색 | / |
| 기본 목적지 / 가능한 보기 | Enter / Alt+Enter |
| 선택 해제 | Escape |
| Text / JSON / Table | Ctrl+2 / Ctrl+3 / Ctrl+4 |
| Metrics / Profile / HVAC / Simulation / Topology | Ctrl+Alt+1 / 2 / 3 / 4 / 6 |
| Topology 3D / Plan / Network | Topology에서 1 / 2 / 3 |
| Topology 맞춤 / 연결 / 면적 / UA / QA | Topology에서 F / T / A / U / Q |

내부 Semantic projection은 식별과 탐색을 지원하며, 노출된 입력 탭이 아닙니다. 해당 내부 projection용 단축키 설정이 있어도 숨겨진 편집기를 열지는 않습니다.

## 근거의 종류 {#evidence}

다음 세 질문에는 서로 다른 근거가 필요합니다.

- **모델 명세:** 입력 객체·참조·지원되는 계산 규칙.
- **엔진 동작:** 실제 실행 입력·출력·달력·ERR 완료 상태.
- **배분 설명:** 관측 소비량·입증된 소유 관계·선택한 회계 정책.

정상 표시, 그럴듯한 그래프, 성공한 내보내기는 각각 해당 검사에 답합니다. 소유 관계 미확인, 출력 미제공, 관측된 0은 매뉴얼 전체에서 구분합니다.

편집은 [입력과 원본 탐색](./input.ko.md), 실행과 결과 해석은 [시뮬레이션](./simulation.ko.md)으로 이어집니다.
