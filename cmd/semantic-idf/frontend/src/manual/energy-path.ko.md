# Energy Path

Energy Path는 저장된 시뮬레이션을 **부하요인 → 열부하 → 최종용도 에너지 → 에너지원** 순서로 읽습니다. 실제 관측값과 명시적으로 구분한 배분을
함께 사용합니다. 열부하 설명과 에너지 회계 화면이며 모델 변경으로
발생할 절감량을 계산하는 화면은 아닙니다.

[Simulation](./simulation.ko.md#purposes)에서 Basic Energy를 실행하세요.
Building/Annual 비교는 [Tools](./tools.ko.md),
파일/API 사용은 [Automation](./automation.ko.md)을 참고하세요.

## 네 단계 읽기 {#reading-the-four-stages}

| 단계 | 물리량 | 영역 | 예시 |
| --- | --- | --- | --- |
| Drivers | 실제 냉방 또는 난방 부하에 배분한 기여량입니다. | 열에너지입니다. | 외벽의 냉방 기여량입니다. |
| Loads | 명시된 경계에서 관측한 열적 서비스입니다. | 열에너지입니다. | 존 현열 냉방입니다. |
| End uses | 장비 또는 직접 용도의 소비량입니다. | 현장 에너지입니다. | 코일 전력량, 조명, 가스 난방입니다. |
| Carriers | 자원별 시설 또는 선택 범위의 소비량입니다. | 현장 에너지입니다. | 전기, 천연가스, 구매 지역냉방입니다. |

열에너지와 현장 에너지는 모두 kWh를 사용할 수 있지만 그래프에서
서로 다른 척도를 사용합니다. 냉방 부하 100 kWh를 전기 25 kWh로
처리할 수 있습니다. 차이 75 kWh는 회계 누락이 아닙니다.
서로 다른 영역의 픽셀 폭 비율로 효율을 구하면 안 됩니다.

Driver와 Load 사이 리본은 양끝에 같은 배분 열량을 사용합니다.
Load와 End use 연결은 서로 다른 열량과 현장 소비량을 유지합니다.
End use와 Carrier 사이 리본은 양끝에 같은 현장 에너지를 사용합니다.

조명 같은 직접 용도는 HVAC 소비가 아니어도 현장 소비에 포함될 수 있습니다.
조명 열취득과 조명 전력량은 관련 원천 근거이며, 보존되는 하나의 물리량을
서로 바꿔 표현한 값은 아닙니다.
재실자 열취득이 구매한 재실자 에너지 용도를 뜻하지도 않습니다.

## Scope, Period, 구성요소 차트 {#scope-and-period}

Scope와 Period의 기본값은 각각 Building과 Annual입니다.
저장된 결과의 **Scope**와 **Period**를 선택합니다.
Building과 Zone은 각각 계산된 회계를 갖습니다.
Zone은 반드시 물리적 사본 한 개를 뜻하지 않습니다.
모델 합계에는 Zone/Group 배수가 포함될 수 있습니다.

Annual과 사용 가능한 월을 화면에서 선택할 수 있습니다.
없는 존, 없는 달, 빈 선택을 다른 존이나 Annual로 대체하지 않습니다.
표시 범위를 바꿔도 모델을 다시 실행하지 않습니다.

냉방과 난방이 함께 표시됩니다. 구성요소를 선택하면 Monthly 또는 Hourly
그래프가 열립니다.

- Monthly는 선택 범위에서 계산한 구성요소 기여량을 보여줍니다.
- Hourly는 실제 보고된 원천 에너지이며 시간별 배분을 만들어 내지 않습니다.
- 월을 선택하면 Hourly 달력도 그 달로 제한됩니다.
- Hourly 식별자, 달력, 면적을 사용할 수 없으면 차트는 사용 불가입니다.

Monthly와 Hourly 그래프는 설정의 **그래프 글꼴 크기**를 따르며,
좁은 영역에서는 그래프 안에서 가로로 스크롤할 수 있습니다.

공유 장비의 Hourly 원천은 Building 측정값일 수 있지만 Monthly 존
기여량은 배분값일 수 있습니다. 두 차트의 합계가 같을 필요는 없습니다.
Hourly 원천을 새롭게 측정한 존 소비량이라고 해석하면 안 됩니다.

실제 Hourly 차트는 일반 Series 미리보기보다 많은 관측값을 가질 수 있습니다.
반올림된 차트 점이 원래 원천도 정확히 0이었다는 근거는 아닙니다.

## 바닥 면적과 면적당 에너지 {#floor-area-and-intensity}

화면의 에너지 물리량은 kWh/m²를 사용하며 소수점 두 자리로 표시합니다.

```text
면적당 에너지 [kWh/m²] = 선택한 에너지 [kWh] / 실행 범위 바닥 면적 [m²]
```

Building은 실행 모델에서 총 바닥 면적에 포함되는 면적을 사용하고
해당 Zone/List 배수를 반영합니다. Zone은 자체 바닥 면적과 해당 배수를
사용합니다. 부하가 0인 플레넘도 모델이 총 면적에 포함하도록 설정했다면
Building 면적에 들어갈 수 있습니다.

분모는 실행에 속합니다. 이후 입력을 편집해도 바뀌지 않습니다.
면적이 없거나 사용할 수 없으면 면적당 에너지는 사용 불가이며 0이 아닙니다.

1,000-m² Building의 2,500 kWh는 2.50 kWh/m²로 표시됩니다.
100-m² Zone의 500 kWh는 5.00 kWh/m²입니다.
분모가 다른 면적당 값을 더하면 안 됩니다. 호환되는 에너지와 면적을
먼저 합산해야 합니다. 존별 면적당 값의 단순 평균은 일반적으로
Building의 면적당 값과 다릅니다.

비율, 백분율, 온도, 물의 체적, 내보낸 절대 에너지 합계는 각자의 단위를
유지합니다.

## Driver 범주와 부호가 있는 열적 압력 {#driver-pressure}

Driver는 관측 변수와 실행 모델의 표면, 존, 경계 관계를 사용해 분류합니다.

| 그룹 | 의미 |
| --- | --- |
| 외벽, 지붕, 지면, 창 | 원천으로 뒷받침되는 표면 교환 또는 창 관련 열입니다. |
| 존 간 표면과 공기 | 모델 존 사이의 교환이며 Building 내부 전달은 새로운 외부 유입이 아닙니다. |
| 재실자, 조명, 장비 | 보고된 내부 열취득입니다. |
| 침기, 기계 환기 | 서로 구분되는 외기 취득/손실 관측값입니다. |
| 팬 또는 기타 HVAC 관련 열 | 열수지에 들어가는 열이며 팬 전력 소비와 구분됩니다. |
| Other/storage | 나머지 부하 설명입니다. 측정된 배터리 대신 미해결 수지/축열을 포함할 수 있습니다. |

표면은 능동 복사 시스템이나 수영장 열교환에 참여할 수 있습니다.
보고된 대류가 언제나 분리된 수동 외피 효과인 것은 아닙니다.
구성체 UA만으로 시뮬레이션 Driver 양을 만들 수 없습니다.

배수를 반영한 부호 있는 압력은 방향을 유지합니다.
양의 열은 냉방 압력을, 음의 열은 난방 압력을 더합니다.
실제 취득/손실 출력은 둘 다 양의 에너지로 보고되더라도 반대 열 방향을
나타낼 수 있습니다.

```text
냉방 압력 P_i = max(배수를 반영한 부호 있는 열 H_i, 0)
난방 압력 P_i = max(-H_i, 0)
```

반대 부호의 압력은 상쇄 맥락으로 남습니다.
추가 음의 부하, 회피 에너지, 절감량을 뜻하지 않습니다.

## 실제 부하에 Driver 배분 {#driver-allocation}

존·월·서비스별로 실제 부하 L과 배분 대상 압력 P를 사용합니다.

```text
Driver 배분량 A_i = L × P_i / 합계(P_j)
```

이 열수지 비율은 결정적인 설명 규칙이지 요금의 인과적 비율이 아닙니다.
합성 수지 폐합 항은 압력 가중치에 들어가지 않습니다.

예를 들어 냉방 부하는 120 kWh이며 외벽 압력은 +60 kWh,
조명은 +40 kWh, 반대 방향 교환은 -30 kWh입니다.

| Driver | 냉방 가중치 | 배분 냉방 기여량 |
| --- | ---: | ---: |
| 외벽 | 60 / 100 | 72 kWh |
| 조명 | 40 / 100 | 48 kWh |
| 반대 방향 교환 | 0 / 100 | 0 kWh |

-30 kWh는 상쇄 근거로 남습니다.
원래 부호 합계는 70 kWh이지만 실제 냉방 부하는 여전히 120 kWh입니다.

실제 부하가 0이면 압력이 있어도 배분량은 0입니다.
양의 부하에 사용할 수 있는 양의 압력이 없으면 원래 압력 0인
Other/storage에 배분합니다. 미설명/축열 기여량을 나타내는 것이며
물리적 열원을 만들어 내는 것은 아닙니다.

관측값이 없다는 사실을 정확히 0인 압력의 근거로 바꿀 수 없습니다.
작지만 실제로 존재하는 신호는 표시 반올림 전에 그 의미를 유지합니다.

## 월별 선계산과 반올림 {#aggregation-and-rounding}

배분은 집계 전에 수행합니다. Annual과 Building은 계산된 존·월
기여량을 합산합니다. 순 연간 압력으로 다시 배분하지 않습니다.

| 월 | 원천의 부호 있는 열 | 실제 서비스 부하 | 계산된 기여량 |
| --- | ---: | ---: | ---: |
| 1월 | -100 kWh | 난방 80 kWh | 난방 80 kWh |
| 7월 | +100 kWh | 냉방 120 kWh | 냉방 120 kWh |
| 연간 근거 | 순합계 0 kWh | 별개 서비스 두 개 | 난방 80 + 냉방 120 kWh |

원천의 연간 순합계가 계절적으로 상쇄되어도 방향별 총 기여량은 없어지지
않습니다. 합계 기여량을 0인 순 원천값으로 나눠 배분 계수를 구하지 않습니다.

계산된 동시 냉난방에는 같은 존·기간의 짝이 필요합니다.
한 존의 냉방과 다른 달의 난방이 동시 운전을 입증하지 않습니다.
고해상도 운전 근거는 자체 관측 경계를 갖습니다.

표시 회계에는 일반적으로 0.001-kWh 단위를 사용합니다.
비례 배분의 내림 몫을 먼저 부여하고 나머지 단위는 소수 잔여가 큰 순서로
배분합니다. 동률은 안정적인 식별자로 정합니다.
각 가지는 자신의 내림/올림 몫 범위에 머물며 원천 예산 합계와 일치합니다.

0.001 kWh를 세 수신자에게 같은 가중치로 나누면 한 곳은 0.001 kWh,
두 곳은 0.000 kWh를 받습니다. 세 곳 모두 0.001을 받으면 예산이 세 배가
됩니다. 소수점 세 자리 회계와 두 자리 면적당 표시는 서로 다른
반올림 단계입니다.

## 직접·배분·미배정 소비량 {#allocation-bases}

| 근거 | 의미 |
| --- | --- |
| 직접/보고 | 정확한 장비 또는 존 관측으로 소비량을 입증하며 유효한 0도 포함합니다. |
| 배분 | 근거가 있는 원천 예산을 서비스 경로나 부하 비율로 분배합니다. |
| 미배정 | Building 소비는 관측했지만 존/서비스별 분할을 입증하지 못했습니다. |

일반 서비스 경로 정책은 정확한 직접 근거를 먼저 사용하고,
일치하는 HVAC 경로의 부하 비율, 같은 서비스의 존 부하 비율을 사용합니다.
나머지 에너지는 미배정으로 남습니다.

직접 소비량은 같은 구분되지 않은 풀에서 차감한 뒤 배분합니다.
그 풀의 나머지를 다시 받아 중복 계산할 수 없습니다.
별도로 관측한 공유 장비는 다른 예산이므로 로컬 장비가 있는 존에도
서비스할 수 있습니다.

팬은 제공되는 경우 완전한 관련 급기 체적 근거를 사용할 수 있고,
그렇지 않으면 근거가 있는 부하 비율을 사용합니다.
펌프와 방열에는 관련 수계/응축기 경로가 필요합니다.
모호한 경로, 불완전한 수신자 목록, 정량화하지 못한 존 외 수요는
배정을 막을 수 있습니다.

예를 들어 A는 직접 소비 30 kWh가 있습니다.
별도 측정한 100-kWh 공유 장비가 유효한 가중치 60/40으로 A/B에 서비스하며,
다른 20-kWh 원천은 수신자 분할을 입증하지 못했습니다.

| 회계 위치 | 물리량 |
| --- | ---: |
| Zone A | 직접 30 + 배분 60 = 90 kWh |
| Zone B | 배분 40 kWh |
| Building 미배정 | 20 kWh |
| Building 합계 | 150 kWh |

존 배정률은 130/150 = 86.67%이지만 Building 소비 회계는 완전히 일치할 수
있습니다. 20 kWh를 어느 존에도 넣지 않습니다.
미배정은 분포가 불확실하다는 뜻이며 Building 에너지가 없다는 뜻은 아닙니다.

## 배수와 소유 관계 {#multipliers}

적용 가능한 대표 존 관측값에는 Zone × ZoneGroup 배수를 한 번 적용합니다.
시설 미터와 이미 모델 합계인 시스템/장비 관측값에는 추가 배수를 적용하지
않습니다. 기하 배수를 실제 결과 에너지에 무조건 다시 곱하지 않습니다.

24-m² 대표 존의 Zone 배수가 2, 그룹 배수가 3이라고 가정해 보세요.
유효 면적은 144 m²입니다. 적용 가능한 대표 냉방 부하 10 kWh는
60 kWh가 되지만 이미 모델 합계인 코일 12 kWh는 12 kWh로 유지됩니다.

해당 면적당 값은 60/144 = 0.4167, 12/144 = 0.0833 kWh/m²이며
0.42, 0.08로 표시됩니다. 코일에 여섯 배를 다시 적용하면
잘못된 소비량이 생깁니다.

존을 나열하는 그룹이 자동으로 배수를 선언하는 것은 아닙니다.
배수 적용 여부를 뒷받침하지 못하면 그 상태를 유지합니다.
보수적으로 배수를 1로 남겼다고 실제로 1이 맞다는 근거가 되지는 않습니다.

## 변환 비율 {#ratios}

보고된 변환은 열부하와 호환되는 현장 소비량을 짝지어 설명합니다.

```text
비율 = 짝지은 열부하 / 짝지은 현장 에너지
연간 비율 = 합계(월별 짝지은 부하) / 합계(월별 짝지은 현장 에너지)
```

| 예시 | 결과 | 의미 |
| --- | ---: | --- |
| 냉방 100 kWh / 전기 25 kWh | 4.00 | 경계와 전기 장비 근거가 뒷받침할 때 COP입니다. |
| 난방 85 kWh / 연료 100 kWh | 0.85 | 연료/장비 경계가 뒷받침할 때 효율입니다. |
| 부하 100 kWh / 지역에너지 125 kWh | 0.80 | 부하/구매 에너지이며 로컬 장비 COP가 아닙니다. |
| 부하 100 kWh / (전기 25 + 가스 10 kWh) | 2.857 | 혼합 자원의 부하/현장 에너지입니다. |

명시된 비율의 의미를 따르세요. 전기 난방이라는 사실만으로 히트펌프 COP를
입증할 수 없습니다. 복사 또는 혼합 열 경계에는 부하/현장 에너지 표시가
필요할 수 있습니다. 수계 구매 에너지가 칠러 전력 소비를 입증하지는 않습니다.

팬/펌프 소비를 코일만의 COP 분모에 조용히 더하지 않습니다.
코일 25 kWh와 팬 5 kWh가 있으면 100/25 = 4와 100/30 = 3.333은
다른 경계를 설명합니다. 보고된 짝 물리량을 사용하세요.

연간 비율은 유효한 짝이 겹치는 기간만 사용합니다.
짝지은 부하를 더 큰 전체 연간 노드 합계로 바꾸거나 월별 COP를 평균하지
않습니다. 분모가 0/없음이거나 짝의 근거가 없으면 비율은 사용 불가입니다.

## 자원, 발전, 저장 {#carriers-and-storage}

소비 자원에는 전기, 가스, 지역냉난방, 증기, 프로판, 연료유와 지원하는
기타 연료가 포함되며 현장 kWh로 정규화합니다.
명시적인 에너지 상당량 변환을 뒷받침하지 못하는 물 체적은 m³ 맥락으로
유지합니다. 체적을 에너지 폐합에 넣지 않습니다.

구매, 생산, 판매, 저장 방전 전기는 공급 맥락이며 추가 최종 용도 소비가
아닙니다. PV 직류 출력, 인버터 교류 출력, 손실, 부대 소비, 저장 전달은
서로 다른 물리 경계를 갖습니다.

검토된 EnergyPlus 25.1 지원 저장 버스의 실제 충전은 계량되지 않은
전달이며 추가 Facility 소비가 아닙니다.
추가 소비/공급 리본 없이 원천 맥락으로 유지할 수 있습니다.
저장 소유 관계, 버전, 배선 분포가 미해결이면 이 경계를 입증하지 못합니다.

저장 장치의 열은 단순히 충전에서 방전을 뺀 값이 아닙니다.
충전 상태 변화, 손실, 회로 경계, 실제 보고 열이 중요합니다.
충전 상태 에너지가 없을 때 관측한 전기값 두 개의 차이로 채울 수 없습니다.

인버터 부대 전기는 소비 용도 예산에 속할 수 있습니다.
상위 소계와 장비 관측값을 동시에 더하면 안 됩니다.

## 품질과 수지 일치 {#quality}

품질 표시줄은 Drivers, Loads, End uses, Carriers를 구분합니다.
단계를 선택해 **Data details**에서 원천 제공 여부를 확인합니다.

| 근거 | 의미 |
| --- | --- |
| 원천 제공 여부 | 적용 가능한 요청 그룹 중 예상 원천을 찾은 정도입니다. |
| Driver/Load 일치 | 배분한 열 기여량이 관측 부하를 설명하는 정도입니다. |
| End use/Carrier 일치 | 소비 용도가 시설 자원 합계를 설명하는 정도입니다. |
| 비율 제공 여부 | 사용 가능한 원천 추적 변환 짝입니다. |
| 존 배정률 | Building 전체 직접+배분 몫과 배정 가능한 HVAC 예산의 관계입니다. |

실행 전체의 제공 여부가 선택한 달의 모든 값을 보장하지는 않습니다.
미상, 요청하지 않음, 해당 없음, 없음, 측정된 0은 서로 다릅니다.

```text
일치율 [%] = 100 × max(0,
  1 - 합계(abs(예상값 - 설명값)) / 합계(예상값))
```

예상값이 각각 100 kWh인 두 항목을 90, 110 kWh로 설명하면 일치율은
90%입니다. 합계가 200 kWh로 같아도 반대 방향 오차를 상쇄하지 않습니다.

중요한 양의 자원 차이는 Unclassified energy로 표시될 수 있습니다.
음의 차이는 과다 매핑 근거로 남습니다.
미분류 잔여를 화면에 더해도 없는 근거가 완전한 측정 용도 근거로
바뀌지는 않습니다. 공급 관측값은 소비 폐합에 들어가지 않습니다.

존을 보고 있어도 존 배정률은 Building 전체 맥락을 유지합니다.
직접/배분 근거가 예산보다 많이 매핑되면 100%를 넘을 수 있습니다.
강제로 제한하여 문제를 숨기지 않습니다.

## Other 그룹과 원천 추적 {#other-and-provenance}

자동 Other 그룹은 해당 범위/서비스/영역에서 1% 미만인 일부 작은
기여량의 표시를 단순화합니다. 원래 원천 기록을 지우거나 내보낼 정식 회계를
변경하지 않습니다. 자원, 중요한 외피/공기 Driver, 부하, HVAC 장비,
보조 용도는 구분된 상태를 유지합니다.

표시 Other는 Other/storage 부하 설명이나 Building 미배정 소비와 다릅니다.
비슷한 라벨이 같은 회계 근거를 입증하지는 않습니다.

의미 있는 추적에는 원래 출력 이름/키, 미터/변수 종류, 빈도,
원천 단위, 정규화 단위, 집계 방법, 관련 모델 소유 관계가 필요합니다.
Monthly 원천 스칼라는 연간 집계일 수 있으므로 없는 달을 채울 수 없습니다.
이름이 같다는 사실만으로 다른 원천의 키, 빈도, 소유 관계, 달력을
대체할 수 없습니다.

## 장비별 해석 경계 {#equipment-boundaries}

아래는 지원하는 회계 방식의 예시입니다.
정확한 원래 장비, 포트, 수신자, 버전, 관측값은 여전히 필요합니다.

### 지역에너지 {#district-energy}

구매 냉난방수는 현장 자원입니다. 존 현열 부하와 부하/구매 에너지로
짝지을 수 있습니다. DOAS 코일이 공기와 물 경로에 함께 있다고 존 전달량이
늘어나지 않습니다. 공유 팬/펌프에는 자체 예산과 수신자 근거가 필요하며
수계 경로만으로 개별 펌프를 측정했다고 볼 수 없습니다.

### 팬코일 {#fan-coil}

냉수와 온수 코일은 각각의 플랜트에 속합니다.
난방 코일을 냉방 플랜트에 연결하는 짝은 유효하지 않습니다.
존 전달량을 알아도 팬/펌프 광역 미터는 미배정 또는 명시적 배분으로
남을 수 있습니다. 작은 실제 부하에 압력이 0이면 원래 정밀도를 유지하고
보수적인 Other/storage 설명을 사용합니다.

### 혼합 난방 연료 {#mixed-heating}

로컬 베이스보드 전기와 중앙 보일러 연료/부대 전기는 독립적인 예산입니다.
같은 존이 둘 다 받을 수 있습니다. 기여 자원별로 같은 짝 열부하를
중복 계산하지 않습니다. 베이스보드 Total Heating과 능동 수열 표면 응답은
겹치는 맥락이며 추가 부하나 에너지가 아닙니다.

### 수영장과 Zone 배수 {#pool}

수영장 온수는 표면과 결합된 공정 수요이며 자동으로 존 공기 난방이
되지는 않습니다. 공정 몫을 정량화하지 못한 수영장/공간 혼합 플랜트는
전체 Heating 소비를 존에 배분할 수 없습니다. 별도로 입증한 냉방 펌프는
자체 예산을 배분할 수 있습니다. 수영장/바닥 대류는 분리된 수동 외피
교환이 아닙니다.

### PTHP {#pthp}

패키지 히트펌프는 DX 냉방, DX 난방, 제상, 크랭크케이스, 보조 연료를
근거가 있는 별도 소비 그룹으로 유지합니다.
난방 크랭크케이스 에너지는 해당 분모에 남습니다.
연료 코일과 DX 코일의 유사한 출력 이름은 정확한 타입 소유 관계를
필요로 합니다. 팬은 코일만의 비율 밖에 있습니다.

### PV와 저장 {#pv-storage}

발전, 인버터 전달/손실, 저장 충방전, 부대 소비는 별도 역할을 유지합니다.
에너지 회계가 완전하다고 모든 열 Driver 요청이 제공되는 것은 아닙니다.
알려진 0 잠열 취득으로 양의 가스 장비 소비를 없앨 수 없습니다.

### 복사 시스템 {#radiant}

능동 표면의 유체 열은 같은 기간의 존 공기 전달량이 아닙니다.
열원, 표면 축열, 대류는 다를 수 있습니다.
명시된 복사/혼합 경계는 공기 전달 COP를 만들지 않고 부하/현장 에너지를
사용합니다. 없는 터미널 코일, 팬, 장비 관측값을 연결만으로 만들지 않습니다.

### VRF {#vrf}

터미널과 실외기 소비는 한 존에 함께 서비스할 수 있습니다.
실외기 주/부대 예산에는 원래 수신자의 완전한 부하 근거가 필요합니다.
수신자를 모른다고 제외해서 나머지 몫을 늘릴 수 없습니다.
냉난방 및 크랭크케이스/제상 소비 그룹은 서비스 경계를 유지합니다.
일부 터미널 근거만으로 완전한 시스템 COP를 얻을 수 없습니다.

### ZoneGroup {#zone-group}

대표 존 물리량에 적용 가능한 Zone·그룹 배수는 한 번만 적용합니다.
실제 로컬 코일/팬/베이스보드 에너지는 이미 모델 합계일 수 있습니다.
겹치는 패키지 합계는 추가 소비가 아닙니다.
HotWaterEquipment는 실내 장비 소비이며 온수를 사용한다고 공간 난방이
되는 것은 아닙니다.

## 내보내기와 비교 {#exports-and-comparison}

**Data details → Data → Export**에서 HTML, XLSX, 전체 실행 JSON을
사용합니다. 요약은 저장된 Scope/Period 선택을 사용하고 전체 실행 JSON은
실행을 보존합니다. 선택적 추적 시트에는 원래 단위, 원천 식별자,
양끝을 독립적으로 평가한 연결 물리량, 제출 JSON이 유지됩니다.

배치 Energy Path 비교는 Building/Annual 맥락을 사용합니다.
없는 행은 Missing이며 0이 아닙니다. 실제 기준값이 0이면 일반적인
변화율을 계산할 수 없습니다. 비교 양쪽의 단위, 근거, 원천 식별자,
품질을 각각 유지합니다.

Driver 비율과 관측 비율은 구성체, 스케줄, 설정값 변경의 절감량을 예측하지
않습니다. 이러한 변경을 비교하려면 같은 엔진/기상/출력 계획으로 통제한
사례를 실행하고 근거가 있는 관측 물리량을 비교하세요.
[Tools](./tools.ko.md)와 [Simulation](./simulation.ko.md#prepare-a-run)을 참고하세요.
