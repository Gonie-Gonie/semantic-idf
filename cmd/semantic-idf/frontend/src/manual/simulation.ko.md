# 시뮬레이션

시뮬레이션은 현재 EnergyPlus 모델을 실행하고 그 결과 관측값을 읽습니다.
정적 분석은 입력 모델을 설명하며, 시뮬레이션은 특정 실행의 엔진, 기상 파일,
출력 계획, 기간에 따른 결과를 설명합니다.

에너지 회계는 [Energy Path](./energy-path.ko.md#reading-the-four-stages),
정적 서비스 연결은 [HVAC](./hvac.ko.md),
여러 파일의 실행은 [Tools](./tools.ko.md)를 참고하세요.

## 실행 준비 {#prepare-a-run}

1. 분석하려는 입력을 열고 편집을 마칩니다.
2. Settings에서 사용할 수 있는 EnergyPlus 설치를 등록합니다.
3. Simulation에서 모델에 필요한 기상 파일을 선택합니다.
4. 조사 목적에 맞는 Purpose를 선택합니다.
5. **Run & Inspect**를 실행합니다.
6. 결과를 해석하기 전에 실행 상태와 ERR 메시지를 확인합니다.

기본 화면은 IDF 또는 epJSON에 선언된 EnergyPlus 버전을 읽고 호환되는
등록 설치를 선택합니다. 호환 엔진이 없거나 설치 버전을 확인할 수 없으면
실행할 수 없습니다. 등록 여부만으로 버전 호환성이 확인되는 것은 아닙니다.

기상 파일은 외기 온도, 습도, 일사, 바람 등의 경계 조건을 제공합니다.
EPW를 바꾸면 다른 실험이 됩니다. 모델에는 설계일이나 실행 기간 설정도
있을 수 있으며, 화면에서 기상을 선택해도 이러한 입력 객체는 대체되지 않습니다.

비교할 때는 의도한 변경 항목을 제외하고 엔진, 기상, 실행 기간, 스케줄,
출력 빈도를 동일하게 유지하세요.

## 실행 사본과 원본 보존 {#run-copy}

Purpose에 필요한 출력 요청은 실행용 사본에 추가됩니다.
실행 과정에서 편집 중인 원본 문서에 출력 요청을 조용히 추가하지 않습니다.

| 항목 | 의미 |
| --- | --- |
| 편집 입력 | 화면에서 보고 저장하는 문서입니다. |
| 실행 입력 | 실행 폴더에 복사되어 실제로 사용된 모델입니다. |
| 임시 출력 추가 | 선택한 Purpose를 위해 필요한 출력 요청입니다. |
| 실행 계획 | 기존 요청과 임시 요청을 포함하여 이번 실행이 요청한 내용입니다. |
| 결과 | 실행 입력으로 생성된 관측값입니다. |

실행 후에도 원본을 편집할 수 있습니다. 저장된 결과는 여전히 실행 당시의
사본을 설명합니다. 이후 면적, 구성체, HVAC 연결을 바꿔도 이전 결과는
소급해서 바뀌지 않습니다.

출력을 원본에 영구 적용하는 작업은 자동화에서 제공하는 별도의 명시적
작업입니다. [Automation](./automation.ko.md)을 참고하세요.
원본 편집과 Run & Inspect의 임시 출력 준비를 구분해야 합니다.

## Purpose 선택 {#purposes}

| Purpose | 확인하려는 내용 | 대표 관측값 |
| --- | --- | --- |
| Basic Energy | 무엇이 열부하와 현장 에너지 소비를 설명하는가? | Energy Path의 월별 회계와 구성요소의 시간별 원천값입니다. |
| Zone Heat Flow | 존 열수지가 시간에 따라 어떻게 변하는가? | 열수지율, 존 온도, 상세 표면 출력입니다. |
| HVAC Loop Check | 실행된 루프에서 무엇이 일어났는가? | 노드 유량·온도·습도·설정값과 장비 운전값입니다. |
| Comfort | 어떤 열환경과 보고된 불쾌적 상태가 발생했는가? | 존/People 온도, PMV, PPD, 습도, 미충족 시간입니다. |

기본 화면은 모든 존, 모든 루프, 전체 실행 기간을 사용합니다.
결과의 Scope/Period 선택은 실행 후 표시 범위를 바꾸는 기능입니다.
한 존이나 한 달을 선택해도 엔진이 그 부분만 다시 실행하지 않습니다.

표준 에너지 배분은 직접 존 소비량을 입증하는 측정값이 없을 때 서비스
경로와 부하 비율을 사용합니다.
[직접·배분·미배정](./energy-path.ko.md#allocation-bases)을 참고하세요.

Integrity와 사용자 정의 출력 기능은 자동화에 존재하지만 기본 화면의
추가 Purpose 선택지는 아닙니다. Batch Simulation은 Basic Energy,
Zone Heat Flow, HVAC Loop Check를 제공합니다.

## 출력 계획과 보고 빈도 {#output-plan}

출력 요청은 미터 또는 변수의 이름, 키, 보고 빈도로 식별합니다.
이름이 비슷하거나 같은 장비를 다른 빈도로 보고한다고 해서 동일한
관측값으로 취급할 수는 없습니다.

| 출력 상태 | 의미 |
| --- | --- |
| 기존 | 이미 원본 모델에서 요청하고 있습니다. |
| 임시 | 이번 실행에만 추가되었습니다. |
| 영구 적용 예정 | 명시적인 영구 적용 작업의 대상입니다. |
| 충돌 | 유사한 대상의 빈도나 필드 구성이 다릅니다. |

에너지 계획은 Monthly 회계 관측값을 유지하고 구성요소 차트에 사용할
실제 Hourly 관측값도 요청합니다. 다른 Purpose가 요청한 일치하는 출력은
재사용할 수 있습니다. 기존 요청의 보고 빈도는 유지됩니다.

월별 에너지는 한 구간의 합계이지 그 달 마지막 한 시간의 값이 아닙니다.
Run Period 합계가 SQL의 마지막 달 시간 행에 연결되어 있어도
그 값은 여전히 전체 실행 기간의 합계입니다.

출력 제공 여부는 엔진 버전과 모델 종류에 따라 달라집니다.
EnergyPlus가 보고할 수 없는 요청 변수는 없는 근거이며 0이 아닙니다.
실행 후 변수·미터 사전은 사용할 수 있는 이름과 별칭을 식별하는 데
도움을 주지만, 사전에 이름이 있다고 측정값까지 존재하는 것은 아닙니다.

## 결과 원천과 부분 결과 {#result-sources}

읽기 우선순위는 SQL, CSV, ESO입니다.

| 원천 | 유용한 정보 | 해석의 한계 |
| --- | --- | --- |
| SQL | 사전 키, 단위, 빈도, 시간 메타데이터, 표 보고서입니다. | 사전 항목만 있고 유효 관측값이 없으면 값을 입증하지 못합니다. |
| CSV | 보고된 열과 시간 라벨입니다. | 일부 메타데이터는 SQL보다 명시적이지 않습니다. |
| ESO | 열수지 관측값의 보완 원천입니다. | 요청한 출력에 따라 제공 여부가 달라집니다. |
| ERR | 엔진 경고, Severe/Fatal 문제, 완료 근거입니다. | 실행을 설명하는 메시지이며 에너지 측정값이 아닙니다. |

결과 섹션마다 실제 원천이 다를 수 있습니다. Heat Flow가 없거나 읽기에
실패해도 정상적으로 읽은 Series를 지우지 않으며, 반대도 마찬가지입니다.
사용할 섹션의 원천과 완전성을 확인하세요.

보완 원천은 없는 섹션을 채울 수 있지만 출력값을 만들어 낼 근거는 아닙니다.
eplusout.sql 파일이 있다는 사실만으로 실행 완료나 에너지 설명의
완전성을 확인할 수는 없습니다.

## 달력, 워밍업, 샘플링 {#calendar-and-sampling}

실제 관측 달력을 사용하세요. 모든 실행이 정확히 8,760시간이라고
가정하면 안 됩니다. 윤년, 일부 기간 실행, 모델 설정에 따라 달라집니다.
EnergyPlus의 구간 종료 라벨에는 24:00이 나타날 수 있으므로
단순한 하루 시간 번호 대신 전체 라벨을 읽어야 합니다.

Hourly HVAC와 Comfort 차트는 SQL에 기상 실행 메타데이터가 있으면
설계일과 워밍업을 제외합니다. 오래된 SQL 구조나 CSV는 제공된 시간축을
사용합니다. 메타데이터가 없다고 기상 달력을 만들어 채우지는 않습니다.

일부 집계 SQL 행은 워밍업 플래그가 NULL입니다. NULL만으로 유효한
Monthly 또는 Run Period 관측값을 워밍업이라고 판정할 수 없습니다.
보고 빈도와 실행 환경 메타데이터도 함께 해석해야 합니다.

일반 Series는 미리보기입니다. SQL은 256개 열, CSV는 16개 열로 제한되며
긴 미리보기는 샘플링될 수 있습니다. 요청한 HVAC/Comfort 관측값과
Energy Path 원천 추적값은 이 제한 밖에서도 별도로 읽습니다.
미리보기가 작다고 원래 실행의 관측값이 적다고 판단하면 안 됩니다.

Heat Flow는 SQL·CSV·ESO의 원본 프레임을 모두 보존합니다. 해당 시각의
선택된 값이 전부 누락되어도 시각 자체는 남깁니다. 원본에 없는 시각은
만들지 않으며 설계일·달력의 기록 순서를 유지합니다. 이전 버전에서 저장한
샘플링 결과는 표시/원본 개수가 그대로 남습니다. 당시 생략된 프레임을
복원하려면 결과를 다시 생성해야 합니다.

## 에너지, 변화율, 단위 {#energy-and-rates}

에너지와 출력은 서로 다른 질문에 답합니다.

| 물리량 | 의미 | 대표 표시 단위 |
| --- | --- | --- |
| 에너지 | 한 구간에 대한 양입니다. | kWh |
| 출력 또는 열전달률 | 관측 구간의 변화율입니다. | W 또는 kW |
| 온도 | 보고된 관측 시점의 상태입니다. | °C |
| 질량 유량 | 초당 통과하는 질량입니다. | kg/s |
| 절대습도비 | 건공기 질량당 수증기량입니다. | g/kg |
| 상대습도 | 포화 상태에 대한 상대적인 정도입니다. | % |

같은 대상의 에너지와 변화율 보완 출력이 함께 있으면 보고된 에너지를
우선합니다. 에너지와 그 변화율의 적분값을 별도 소비량으로 더하지 않습니다.

```text
에너지 [kWh] = 보고된 줄(J) / 3,600,000
변화율로 계산한 에너지 [kWh] = 합계(변화율 [W] × 구간 [시간]) / 1,000
```

예를 들어 2,000 W가 15분 동안 유지되면 0.5 kWh입니다.
W 값 네 개를 더한 8,000 W는 2 kWh가 아닙니다. 시간 구간을 반영하여
적분해야 합니다. 없는 구간을 0으로 관측한 운전이라고 간주하면 안 됩니다.

Energy Path는 열에너지와 현장 에너지를 실행 모델의 바닥 면적으로 나눠
표시합니다. [면적당 에너지](./energy-path.ko.md#floor-area-and-intensity)를
참고하세요. HVAC 변화율과 Comfort 상태 차트는 각자의 단위를 유지합니다.

## 없음, 0, 사용 불가 {#missing-data}

| 표시 또는 근거 | 의미 |
| --- | --- |
| 측정된 0 | 유효한 보고 값이 0입니다. |
| 없음 또는 사용 불가 | 필요한 관측값이나 분모가 없거나 유효하지 않습니다. |
| 요청하지 않음 | 이번 실행 계획에 포함하지 않은 출력 그룹입니다. |
| 해당 없음 | 모델/계획에 적용되는 관측 그룹이 없습니다. |
| 모호함 | 여러 식별자나 상충하는 관측 때문에 값을 하나로 정할 수 없습니다. |

평평해 보이는 차트에 반올림된 작은 값이 들어 있을 수 있습니다.
반대로 선이 없거나 차트가 사용 불가라고 해서 에너지가 0인 실행은 아닙니다.
없는 관측값을 인접 시간, 다른 존, Building 값으로 대체하면 안 됩니다.

## Heat-Flow Ledger {#heat-flow-ledger}

작은 층별 평면도에서 존 번호를 선택하면 오른쪽 원장에서 현재 시각의 값을
확인할 수 있습니다. 번호는 모델 전체에서 고유합니다. 플래넘처럼 바닥 조각이
여러 개인 존도 번호와 Local 막대는 하나만 표시합니다. 평면도는 카드 크기에
맞춰 고정하며, 휠·드래그·두 번 클릭으로 확대하거나 이동하지 않습니다.
평면도 아래의 **존별 수치**를 펼치면 Local Gain, Local Loss와 전체 Net을 볼 수
있습니다.
평면도를 보기 쉽도록 표와 읽는 법은 처음에 접어 둡니다.
열류율은 부호가 있는 kW로 소수점 둘째 자리까지, 온도는 °C로 표시합니다.
반올림은 표시 문자열에만 적용하며 막대·색상·합계는 보존된 값으로 계산합니다.
반올림하면 0이 되는 열류율은 `0.00 kW`로 표시하고 W 툴팁에는 원래 부호를 유지합니다.
수치 위에 마우스를 올리면 결과에 보존된 W 값을 볼 수 있습니다.
양수는 Zone 공기에 열을 더하고 음수는 열을 제거합니다. 서로 상쇄되어
Net이 작아도 열획득과 열손실은 따로 확인할 수 있습니다.
Local 막대와 Net 색상은 모든 존과 보존된 전체 시각에 공통인 고정 로그
척도를 사용합니다. 같은 Local 합계는 같은 높이, 같은 Net은 같은 색상을
재생이나 층 필터 변경 시에도 유지합니다. 범례의 최대값은 전체 결과에서 한 번 계산하며 선택한
시각에 따라 바꾸지 않습니다. 온도 색상은 보고된 온도 범위를 유지합니다.
0은 중립색으로 남고, 누락된 평면도 관측값은 사선 무늬로 표시합니다.
Local 항목이 모두 누락되면 실제 0처럼 보이는 기준선을 그리지 않습니다.

로그 크기는 `ln(1 + abs(q)/1 W) / ln(1 + 최대값/1 W)`로 계산합니다.
0에서도 연속적이며 양수와 음수를 모두 처리합니다. Net 색상은 Net 절대값의
최대값을, Local 막대는 양·음 Local 합계의 최대값을 기준으로 합니다.
각 부호의 전체 막대 높이에 로그 크기를 적용하고, 항목별 조각은 해당 합계
안에서 원래 비율을 유지합니다. 큰 피크 옆의 작은 열전달도 보이게 하는
척도이므로 막대 높이나 색상 진하기가 열량의 선형 비율을 뜻하지는 않습니다.

오른쪽 원장은 Local 항목, Zone 전체 열교환, 별도의 Storage/Balance 진단값을
가로 막대와 정확한 부호 있는 수치로 표시합니다. 가운데 0을 기준으로 손실은
왼쪽, 획득은 오른쪽으로 그립니다. 모든 열류율 막대는 전체 존과 시각에
공통인 고정 로그 kW 척도를 사용하며 양 끝의 값을 표시합니다. 누락된 관측값은 0
막대 대신 사용 불가로 구분합니다. 관측된 표면 열교환 에너지는 보고 구간당
kWh로 별도 표시합니다. 정확한 비교는 수치를, 선형 열류율 그래프는 History를
참고합니다.
엔진과 실행 입력의 기준이 검증된 새 결과에서는 System air transfer를
EnergyPlus 보고값 ÷ Zone × ZoneList multiplier로 계산해 한 존 기준으로
맞춥니다. System convective gain은 실행 입력에 High-temperature radiant
장비와 Indoor pool이 없을 때만 같은 보정을 적용합니다. 그 밖에는 구성
성분의 기준이 섞일 수 있어 보고 합계를 유지하고 안내를 표시합니다.
보정된 HVAC 수치 위에 마우스를 올리면 엔진의 원래 W 값과 나눈 배수를
볼 수 있습니다. 일반 시계열과 원본 출력 파일은 보고값을 유지합니다.
기준 정보가 없는 이전 저장 결과는 기존 값을 유지하므로 보정된 원장과
원천 기준 정보를 얻으려면 다시 실행합니다. Reported deviation은 엔진의
원래 진단값이며 보정 후 계산한 Net − Storage residual과 다를 수 있습니다.

| 그룹 | 포함되는 열전달 항목 | 의미 |
| --- | --- | --- |
| Local gains / losses | Internal convective gains | 사람, 조명, 장비 등에서 Zone 공기로 전달되는 대류열. |
| Local gains / losses | HVAC system air transfer | HVAC 공급 공기로 전달하거나 제거하는 열. |
| Local gains / losses | HVAC/system convective gains | 공기 공급 방식이 아닌 HVAC 장비의 직접 대류열. |
| Boundary exchange | Surface convection | 모든 Zone 표면과 Zone 공기 사이의 열전달 합계. |
| Boundary exchange | Interzone air transfer | 다른 Zone과의 공기 교환에 따른 열전달 합계. |
| Boundary exchange | Outdoor air transfer | 침기 등을 포함한 외부 공기의 열전달 합계. |

```text
Net = 위 여섯 가지 열전달 항목의 합
Balance residual = Net − Air energy storage
```

**Air energy storage**와 **Reported balance deviation**은 열전달 항목과
분리하여 표시합니다. Storage가 양수이면 공기 온도가 오르며 축열하고,
음수이면 공기 온도가 내려가며 열을 방출합니다. 둘은 Net에 더하는 추가
열획득이나 열손실이 아닙니다. 계산한 residual은 여섯 열전달 항목과 Storage가
모두 관측된 경우에만 제공합니다. 별도로 보고된 deviation은 원래 부호를
유지합니다. 이는 [EnergyPlus Zone 공기 열수지식](https://github.com/NREL/EnergyPlus/blob/v25.1.0/src/EnergyPlus/ZoneTempPredictorCorrector.cc#L4981)을 따릅니다.

`*`는 일부 항목만 있는 Net입니다. 누락된 값을 0으로 간주하지 않고 관측된
항목만 합산합니다. 사용 불가 수치나 차트의 빈 구간은 실제로 보고된 0과
다릅니다. 새 결과는 Zone·항목·시각별 값과 온도의 관측 여부를 기록합니다.
이전 저장 결과는 원래 배열을 유지하므로, 채워 넣은 0과 미관측 값을 구분할
근거가 없을 수 있습니다. 다시 실행하면 이 근거를 확보할 수 있습니다.

**교환 화살표**는 선택한 Zone으로 들어오거나 나가는 방향을 표시합니다.
공기 교환과 Surface convection 행은 Zone 전체의 kW 합계이며 특정 이웃
Zone에 배분하지 않습니다. 별도의 측정된 표면 화살표는 실행 모델에서 확인된
Zone이나 외부 경계를 연결합니다. 검증된 Hourly 원천 관측값과 현재 시각이
정확히 일치하고 지원하는 열류율 또는 에너지 단위가 명시되어야 합니다.
열류율을 적분한 에너지는 실제 적분 구간이 1시간으로 검증되어야 합니다.
직접 보고된 Hourly
J/kWh 에너지는 다른 시간이 누락되어도 원천 관측 시각들이 일치하면 사용할
수 있습니다. 상호 대응하는 Zone 간 표면은 한 계면으로 한 번만
계산하며 원천 식별자는 유지합니다. 유입과 유출 에너지는 각각
**보고 구간당 kWh**로 표시합니다. 표면 전도와 창 열교환은 Zone 공기 대류
원장과 다른 물리량이므로 kW Net에 더하면 안 됩니다. 관측값이 없거나 검증되지
않은 계면에는 측정 화살표를 표시하지 않습니다. 이전 결과는 Surface-detail로
다시 실행해야 실행 Geometry와 프레임 근거를 확보할 수 있습니다.

보이는 존 번호끼리 존 쌍당 순교환 화살표 하나로 연결하며, 서로 다른 층의
존도 두 번호가 보이면 연결합니다. 관측된 외부 방향은 모두 합쳐 **외부**
화살표 하나로 표시합니다. Ground와 Adiabatic 경계는 외부 교환에 포함하지
않고, 숨겨진 존을 평면 가장자리의 외부 이름으로 대체하지 않습니다.
방향은 유입 에너지에서 유출 에너지를 뺀 값으로 결정합니다. 유입과 유출이
균형인 교환은 회색 양방향 화살표 하나로 표시합니다. **관측된 표면 열교환**을
펼치면 원래의 유입·유출 값을 각각 볼 수 있습니다. 합쳐진 화살표도 검증된
관측값만 합산하며 미관측 경계의 값을 추정하지 않습니다.

**Heat-flow history**는 결과 영역의 전체 폭을 사용하며 Local 열전달,
Boundary exchange, 보고된 Storage/Deviation의 세 패널로 나눕니다.
패널은 같은 부호와 축 범위를 사용하며 진단값의 보고 부호를 유지합니다.
축의 단위를 확인하세요. 글꼴은 UI 및 **Settings → Graph label font size**를
따르며 읽을 수 있는 최소 크기를 유지합니다. 좁은 패널은 가로로 스크롤할 수
있습니다.
그래프를 클릭하면 프레임을 선택합니다. 스크롤로 범위를 확대·축소하고,
Shift+스크롤로 이동하며 두 번 클릭하면 전체 범위로 복원합니다.
범례에는 선택한 프레임의 값을 표시합니다. 유효하고 증가하는 시각은 실제
경과 시간 간격으로 배치합니다. 역행·중복·미확인 시각은 결과 기록 순서임을
명시하여 표시하고, 관측 사이의 누락 구간을 채우지 않습니다.
**24시간**, **7일**, **30일**은 선택한 시각 주변에서 해당 길이의
범위를 선택합니다. 연속된 달력 시각 범위 안에서 동작하며 날짜가 유효하지
않거나 이전 날짜로 되돌아가는 경계에서는 프레임 개수로 대신 계산하지 않습니다.

**재생**은 선택한 범위의 원본 프레임을 하나씩 보여준 뒤 처음으로 돌아갑니다.
시간별 데이터는 1시간씩 진행하고, 원본에 실제로 빠진 시각은 채우지 않습니다.
**느림 / 보통 / 빠름**은 화면 전환 간격만 900 / 420 / 160 ms로 바꾸며
관측값을 건너뛰지 않습니다. 일시정지·속도 변경은 현재 프레임을 유지하고,
시간 슬라이더로 이동한 뒤에도 선택한 프레임부터 이어집니다. Heat Flow를
떠나면 재생이 멈춥니다. 재생 중에는 History 경로를 유지하면서 커서·존 색상·
막대·화살표·정확한 수치를 함께 갱신합니다.

History는 원본 프레임을 stride sampling이나 평균화 없이 모두 그립니다.
프레임 수와 시각을 함께 확인하세요. 표시된 24개 기록이 반드시 하루를 뜻하지는
않습니다. W 값을 에너지로 적분하려면 실제 시간 간격이 필요하므로 연간 kWh는
적분된 에너지 결과를 사용하세요.

정적 Topology의 UA는 W/K 단위 열전달 계수입니다.
기상, 운전 시간, 온도차를 포함하지 않습니다. 예를 들어 UA가 100 W/K이고
정상 상태에서 온도차가 10 K라면 단순 계산은 1,000 W이지만, 이 값이
모델에서 시뮬레이션한 시간별 표면 열류는 아닙니다. 축열, 일사,
스케줄, 변화하는 경계 조건은 여전히 영향을 줍니다.

정적 연결과 구성체 정보의 완전성은 [Topology](./topology.ko.md)를
참고하세요. 시뮬레이션 결과는 정적 Topology 지표에 섞이지 않습니다.

## HVAC 프레임 검사 {#hvac-frames}

사용할 수 있는 실행 루프를 선택하고 관측 프레임을 이동합니다.
편집 모델이 바뀌었더라도 다이어그램은 해당 실행의 장비와 노드 연결을
유지합니다.

노드에는 질량 유량, 온도, 습도, 정의된 설정값이 표시될 수 있습니다.
장비는 출력이 있을 때 전력, 부하, 운전 비율, 에너지, 보고된 COP 등의
속성을 제공합니다.

- 사용 가능한 0 유량도 측정값입니다.
- 없는 값은 사용 불가로 유지하며 이전 프레임을 재사용하지 않습니다.
- EnergyPlus의 미설정 온도 설정값 -999와 아주 작은 반올림 오차는
  설정값 표시와 편차 계산에서 제외됩니다.
- 유효한 0 또는 음수 온도 설정값은 미설정 플래그가 아닙니다.
- 설정값이 없다는 이유만으로 제어 이상을 판정하지 않습니다.
- 실행 연결이 없는 오래된 저장 결과는 관측값을 보유할 수 있지만
  루프 다이어그램은 사용 불가일 수 있습니다.

폭이 좁은 회로 화면에서는 가로로 스크롤할 수 있습니다.
측정 라벨이 많으면 주변 공간을 늘리며 물리적 연결의 의미를 바꾸지 않습니다.
계통도에는 실제 표시된 계통의 노드와 장비에 대응하는 값만 표시합니다.
유형과 이름으로 부모 장비가 하나로 확인되는 내부 장비는 부모 위치에 표시합니다.
계통 내 표시 위치가 없는 관측값은 그래프 선택에서 확인할 수 있습니다.
공유 장비의 다른 회로 포트나 위치가 확인되지 않는 값은 계통도에 별도 라벨로
나열하지 않습니다.

## HVAC 시계열과 산점도 {#hvac-charts}

기본 차트는 노드 유량, 온도, 습도를 보여줍니다.
노드별 선택으로 비교할 추적값을 정합니다.
Y축 범위와 Auto 초기화는 서로 다른 단위에 독립적으로 적용됩니다.
HVAC·Comfort 그래프는 앱 글꼴과 Settings의 그래프 글자 크기를 따릅니다.
글자를 크게 설정하면 읽을 수 있는 그래프 폭을 유지하며, 좁은 화면에서는
가로로 스크롤할 수 있습니다.

사용자 차트는 장비/노드를 먼저 선택하고 속성을 선택합니다.
선 차트는 서로 다른 Y축에서 최대 두 단위를 사용합니다.
산점도는 같은 관측 시점에 있는 정확히 두 속성을 비교합니다.

기본 관측값은 원천 행 식별자로 정렬합니다. 다른 파일은 양쪽에서
시간 라벨이 유일할 때만 그 라벨로 연결할 수 있습니다.
중복되거나 모호한 관측값은 임의로 연결하지 않고 빈 구간으로 남깁니다.

예를 들어 12:00의 온도와 12:15에만 있는 유량은 하나의 산점도 점을
입증하지 못합니다. 겹치는 시간이 없으면 짝지을 근거가 없는 것이며,
물리적 관계가 없다는 증거는 아닙니다.

습도는 상대습도가 있으면 이를 사용하고, 그렇지 않으면 g/kg 단위의
절대습도비를 사용할 수 있습니다. 둘은 다른 물리량입니다.
축 범위를 비슷하게 표시해도 서로 변환되는 것은 아닙니다.

## Comfort 해석 {#comfort}

Comfort는 상태 관측 화면이며 에너지 회계 화면이 아닙니다.

| 추적값 또는 지표 | 의미 |
| --- | --- |
| T | 존 공기 온도입니다. |
| Top | 제공되는 경우 보고된 작용 온도입니다. |
| Tmrt | 보고된 평균 복사 온도입니다. |
| Tset,h / Tset,c | 난방/냉방 온도 설정값입니다. |
| PMV | 보고된 쾌적 모델의 예상 평균 온열감입니다. |
| PPD | 보고된 예상 불만족 비율이며 % 단위입니다. |
| RH / w | 상대습도 / 절대습도비입니다. |
| 미충족 시간 | 보고된 설정값 또는 쾌적 조건 미충족 시간이며 시간(h) 단위입니다. |

PMV/PPD의 키는 People 객체일 수 있습니다. 실제 소유 존에 연결하며,
서로 다른 People 그룹은 별도 추적값으로 유지됩니다.
가정은 입력의 쾌적 모델, 활동량, 착의량, 스케줄, 환경 조건에 달려 있습니다.
보고되지 않은 People 그룹의 쾌적 결과를 추정하지 않습니다.

지표는 사용 가능한 관측값의 평균/범위 또는 보고된 미충족 시간을 사용합니다.
시계열 평균은 존재하는 관측값의 평균이며, 반드시 재실 가중 노출량을
의미하지는 않습니다.

Building 지표에는 실제 시설 전체 관측값이 필요합니다.
존 PMV를 평균하여 Building PMV를 만들지 않으며 존 미충족 시간을 더해서
시설 합계를 만들지 않습니다. 여러 존의 미충족 시간은 동시에 발생할 수 있습니다.

자동화의 사용자 지정 기간에서는 전체 기간 표 보고서의 미충족 시간을
생략합니다. 그 값이 선택 구간을 설명하지 않기 때문입니다.
기본 화면은 전체 기간을 사용합니다. 추세 없이 표 보고서 시간만 있는 존도
지표를 가질 수 있지만 시간별 차트를 만들어 채우지는 않습니다.

## 실행, 수신, 오류 {#run-status}

단계 표시는 엔진 실행, 읽기, 결과 구성, 수신, 표시를 구분합니다.
전체 작업량을 알 수 있는 구간은 실제 처리량을 표시합니다. SQL 읽기는
행 수를 세기 위해 데이터베이스를 다시 읽지 않고, 기존 읽기 과정에서 처리한
관측 행 수를 알립니다. 숫자 없이 움직이는 막대는 전체 작업량이 아직
확인되지 않았다는 뜻이며, 경과 시간과 현재 작업은 계속 갱신됩니다.

같은 앱 세션에서 일치하는 실행을 성공적으로 마친 뒤에는 `≈` 진행률과
남은 시간 범위를 표시할 수 있습니다. 입력, 목적·상세 수준·범위, 엔진,
기상과 실행 설정이 같은 측정을 사용합니다. 한 번의 측정에서는 넓은 초기
범위를 표시하며, 추가 측정으로 범위를 보완합니다. SQL 읽기와 결과 구성을
포함한 백엔드 처리 시간의 추정이며, 결과 전송이나 화면 표시까지의 정확한
완료 시각을 약속하지 않습니다. 입력이 바뀌면 추정 없이 시작합니다.
측정 범위를 넘기면 작업 중에 0초를 표시하지 않고 남은 시간을 미확정으로
되돌립니다.

엔진의 Warmup, sizing, 시뮬레이션 날짜는 실제 수행 중인 작업을 나타냅니다.
Design Day, 여러 RunPeriod와 Warmup의 비용이 다르므로 시뮬레이션 날짜를
벽시계 시간의 진행률로 취급하지 않습니다. 수신 단계는 응답 크기를 알 때
실제 수신한 바이트를 표시하며, 결과 해석과 화면 표시는 별도 단계입니다.
전체 완료의 100%는 결과를 화면에 설치한 뒤에 표시합니다. 개별 단계가 먼저
끝나는 경우에는 해당 단계의 진행률임을 명시합니다.

시간 측정은 크기를 제한한 메모리에만 보관합니다. 실행기록 파일을 추가로
만들지 않으며 앱을 다시 시작하면 초기화됩니다. Batch 진행에는 완료 파일,
실행 중·대기 중 작업 수와 현재 파일의 단계가 표시됩니다. 파일마다 크기가
다르고 병렬 실행의 부하도 달라, 완료 파일 수만으로 남은 시간을 예측하지
않습니다.

엔진이 완료되어도 모든 결과가 표시된 것은 아닙니다.
큰 실행은 SQL 읽기, 회계 구성, 데이터 전송, 그래프 준비에 추가 시간이
걸릴 수 있습니다. 수신이나 표시 문제는 엔진 오류와 구분하여 확인해야 합니다.

ERR 심각도와 완료 상태를 함께 보세요. 경고는 사용할 수 없는 출력 요청이나
모델 문제를 알릴 수 있습니다. Severe/Fatal 문제 또는 미완료 실행은
물리량을 완전한 실험 결과로 사용하기 전에 검토해야 합니다.
일부 결과가 있다는 사실만으로 문제가 없는 실행이라고 판정할 수는 없습니다.

## 저장 결과, 전송, 내보내기 {#saved-results}

저장 결과는 현재 편집기가 아니라 실행 모델에 연결됩니다.
보관한 결과를 복원하거나 내보내도 EnergyPlus를 다시 실행하지 않습니다.

큰 데스크톱 응답은 동일한 시간축과 숫자 열을 공유할 수 있습니다.
관측값과 순서를 유지하는 방식이며 차트 다운샘플링이 아닙니다.
열지 않은 HVAC 루프는 검사하기 전까지 압축된 형태로 유지될 수 있습니다.

Energy Path의 **Data details → Data → Export**에서 HTML, XLSX,
전체 실행 JSON을 제공합니다. 요약은 선택한 Scope/Period를 유지하고,
전체 실행 JSON은 보관한 실행을 유지합니다. 선택적 XLSX 추적 시트에는
원천 참조, 단위, 연결 양끝의 물리량, 원래 제출 데이터가 유지됩니다.

비교 근거를 보관할 때는 실행 입력, 실행 계획, ERR, SQL 또는 보완 파일,
기상 식별 정보를 함께 유지하세요. 내보낸 합계만으로는 어떤 출력,
단위, 가정으로 결과를 얻었는지 설명할 수 없습니다.

## 문제 확인과 배치 작업 {#troubleshooting}

| 현상 | 먼저 확인할 내용 |
| --- | --- |
| 실행 불가 | 호환 엔진 등록, 감지한 입력 버전, 필요한 기상입니다. |
| 엔진 완료 후에도 화면이 처리 중 | 읽기/구성/수신 단계인지 확인합니다. 엔진이 계속 실행 중이라고 단정하지 않습니다. |
| 에너지 구성요소의 Hourly 차트 없음 | 실제 Hourly 요청, 정확한 키/빈도, 완전한 달력, 유효한 바닥 면적입니다. |
| HVAC 속성 없음 | 실행이 해당 속성을 보고했는지, 프레임과 정렬되는지 확인합니다. |
| Comfort Building 비어 있음 | 실제 시설 관측값이 필요하며 존 데이터로 대체하지 않습니다. |
| 비교값의 예상 밖 차이 | 실행 입력, 엔진, 기상, 기간, 빈도, 배분 방식, 없음과 0의 차이입니다. |

배치 작업자는 독립적인 입력을 제한된 동시 실행 수로 처리합니다.
파일마다 호환 엔진과 기상 연결이 필요하며 한 입력의 버전 불일치가
다른 호환 파일까지 실패시키지는 않습니다. 작업자 수는 처리량 선택이며
물리량의 의미를 바꾸지 않습니다. [배치 작업](./tools.ko.md)을 참고하세요.
