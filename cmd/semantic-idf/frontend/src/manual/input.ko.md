# 입력, 편집과 원본 탐색

Text, JSON, Table은 하나의 작업 중인 EnergyPlus 모델을 보여줍니다. 어느
뷰에서 값을 수정하든 모든 분석 탭이 사용하는 문서가 변경됩니다. 세 뷰는
파싱된 객체의 표현 방식이며, 별도로 저장되는 세 문서가 아닙니다.

## 모델 열기와 식별 {#load-model}

**Open**으로 IDF 또는 epJSON 파일을 엽니다. 제목과 상태 표시에서 열린
파일을 확인합니다. 문서가 설치되면 분석이 시작되며 Metrics와 입력 뷰가
먼저 준비되고, 비교적 무거운 Profile, HVAC, Topology 단계가 뒤따릅니다.
대기 중인 패널은 아직 현재 모델의 보고서를 받지 않은 상태입니다.

모델의 **Version** 객체에서 EnergyPlus 버전을 읽습니다. 버전 문자열을
읽었다고 설치된 엔진이 해당 모델을 실행할 수 있음이 보장되지는 않습니다.
IDF는 순서가 있는 객체와 필드를, epJSON은 이름이 있는 객체 맵과 스키마
필드를 사용합니다. 공학적 의미가 같아도 두 형식의 구조는 다릅니다.

객체 이름은 실제 이름 필드가 있을 때 그 필드에서 가져옵니다. 이름이
없는 객체는 유형/인덱스로 식별합니다. 이름 없는 객체에 표시된 번호는
분석기의 원본 식별자이며 새로 만든 EnergyPlus 이름이 아닙니다. 중복
이름은 참조 해석을 모호하게 만들 수 있습니다. 클릭한 정의가 유일한
대상이라고 판단하기 전에 Diagnose를 확인합니다.

다른 파일을 열면 작업 문서가 바뀝니다. 보존할 편집은 파일을 바꾸기 전에
저장합니다. 기본 Large Office 예제는 시작용 모델이며, 사용자의 모델에도
같은 수준의 정보가 있다는 근거가 되지는 않습니다.

## 입력 뷰 선택 {#input-views}

| 뷰 | 적합한 용도 | 표시의 의미 |
| --- | --- | --- |
| Text | 익숙한 IDF 객체/필드 순서 확인과 개별 값 편집 | 형식화된 객체 표시이며 자유로운 코드 편집기는 아님 |
| JSON | 스키마 형태, 배열과 값의 자료형 확인 | 키·구두점·구조 토큰은 읽기 전용이며 값 편집은 공통 모델에 적용 |
| Table | 동일 유형의 반복 객체 비교 | 객체를 행 또는 열로 배치하며 헤더는 원본 객체/필드에 연결 |

Text와 Table의 객체 그룹은 처음에 펼쳐져 있습니다. 필요한 그룹만 남기고
접으면 표시를 단순화할 수 있습니다. Table의 전체 방향 버튼 또는 객체
유형별 방향 버튼으로 전치합니다. 전치는 표시를 바꾸며 모델과 필드
순서를 변경하지 않습니다.

Table은 한 번에 필터와 일치하는 객체 최대 500개를 표시합니다. 추가
객체가 숨겨졌다는 안내는 나머지 일치 항목이 있다는 뜻이며 삭제되거나
분석에서 제외되었다는 뜻이 아닙니다. 필터를 좁혀 확인합니다. 분석과
내보내기는 이 표시 제한과 독립적으로 전체 모델을 사용합니다.

IDF를 열었더라도 JSON 뷰는 epJSON 표현을 보여줍니다. JSON을 본다고
디스크 파일이 변환되지는 않습니다. 상세 표면 좌표는 스키마에 맞는
`vertices` 배열로 표시되며 x/y/z는 각각의 값입니다. 기하를 수정할 때
좌표의 단위와 순서를 보존합니다.

## 객체 필터와 값 찾기 {#filter-objects}

공통 필터는 객체 유형, 실제 이름 또는 원본 인덱스, 필드 이름과 값을
검색합니다. 공백으로 구분한 검색어는 대소문자를 구분하지 않으며 모든
검색어가 해당 객체의 검색 대상 내용 어딘가에 있어야 합니다. 같은
필드에 모두 있어야 하는 것은 아닙니다.

예를 들어 `Lights Office`는 검색 대상 유형/이름/필드에 두 단어를 모두
포함하는 객체를 찾습니다. `Watts 12`는 계산 방식과 값이 함께 있는
객체를 찾을 수 있습니다. 이는 문자열 검색이며 수치 비교나 정규식
검색이 아닙니다. 검색 결과가 있다고 계산 방식이 해석된 것은 아닙니다.

입력 뷰를 바꾸어도 공통 필터가 유지됩니다. 선택 때문에 숨겨진 객체가
임시로 드러나더라도 원래 필터는 남아 있습니다. 임시 표시나 선택을
해제하면 기존 필터 결과로 돌아갑니다. 일치하는 객체가 없다는 안내를
보면, 실제로 그 유형의 객체가 없는지 판단하기 전에 필터를 지웁니다.

## 값 편집과 확인 {#edit-values}

Text 또는 Table에서는 값 입력란에 포커스를 주고 새 값을 입력합니다.
**Enter** 또는 입력란에서 벗어나는 동작으로 적용합니다. **Escape**는
편집하던 입력란의 기존 값을 복원합니다. 추천 값은 참조 이름을 찾는 데
도움이 되지만 모델 전체가 유효함을 보장하지는 않습니다.

JSON에서는 편집 가능한 값 토큰을 활성화합니다. `0.5`와 같은 숫자,
`"Always On"`과 같은 따옴표가 있는 문자열 또는 스키마에 맞는 값을
입력합니다. **Enter** 또는 편집기에서 벗어나면 적용하고 **Escape**로
현재 토큰 편집을 취소합니다. 잘못된 JSON은 패치 전에 거부됩니다.

수정은 원본 객체/필드 또는 중첩 JSON 경로에 적용됩니다. 문서를 다시
파싱하고 분석 결과를 갱신합니다. 갱신 전의 파생 값은 아직 대기 상태일
수 있습니다. 이전에 보이던 결과를 새 값의 검증 결과로 해석하지 않습니다.

빈 값, `0`, `Autosize`, `Autocalculate`는 서로 다른 입력입니다. 빈 값은
EnergyPlus 기본값을 사용하게 하거나 필수 참조를 빠뜨릴 수 있습니다.
0은 수치입니다. Autosize/Autocalculate는 엔진이 값을 결정하도록 하는
지시이며, 정적 분석기가 항상 해석할 수 있는 측정 설계값이 아닙니다.

참조를 수정할 때 특히 주의합니다. 정의의 이름을 바꾸었다고 모든 참조
필드가 자동으로 바뀐다는 보장은 없습니다. Definition/References와
Diagnose에서 관련 관계를 확인합니다.

### 예: 조명 밀도 변경 {#lighting-edit-example}

1. 의도한 `Lights` 객체와 Zone 또는 Space 대상을 필터로 찾습니다.
2. 계산 방식이 `Watts/Area`인지 확인한 뒤 해당 값을 수정합니다.
3. 10을 12 W/m²로 바꾸고 적용합니다.
4. 현재 Metrics/Profile 분석을 기다립니다. 면적이 해석되는 100 m²
   단일 인스턴스라면 설계 전력이 1000 W에서 1200 W로 바뀝니다.
5. 대상, 스케줄, 승수를 확인합니다. 연간 조명 에너지는 시뮬레이션이
   필요하며 변경된 정적 전력은 연간 kWh가 아닙니다.
6. 원본과 분석 결과를 확인한 뒤 모델을 저장합니다.

## 저장, 되돌리기와 형식 {#save-revert}

**Save**는 현재 작업 문서를 열린 파일에 씁니다. 문서에 경로가 없으면
저장 위치를 선택합니다. 저장 대화상자를 취소하면 문서는 메모리에
남습니다. 저장 오류가 발생해도 작업 문서를 수정하거나 다른 위치에
저장할 수 있습니다.

**Revert**는 처음 불러온 텍스트로 되돌립니다. 편집 취소 스택이 아니며
마지막으로 저장한 텍스트와 같다고 볼 수도 없습니다. 수정한 문서를
저장해도 최초 로드 기준은 바뀌지 않습니다. 복원된 문서에 대해 분석을
다시 수행합니다. 복원 내용을 디스크에도 쓰려는 경우에만 다시 저장합니다.

일반 필드/Profile/HVAC 편집은 입력의 원래 형식으로 저장됩니다. JSON
탭 전환은 표시 변경입니다. 직렬화 과정에서 서식, 필드 표현이나 생성
라벨이 정규화될 수 있으므로 바이트를 그대로 보존하는 편집기는 아닙니다.
주석과 원래 서식이 중요하면 원본 파일을 보관하고 저장 결과를 검토합니다.

IDF와 epJSON 변환은 버전별 객체 스키마와 필드 매핑에 의존합니다. JSON
표현으로 매핑을 확인할 수 있지만 기본 입력 탭에는 독립된 형식 변환
명령이 없습니다. 파일 확장자만 바꾸는 것은 내용 변환이 아닙니다.

정리와 자동 수정은 **Tools / Diagnose**에서 명시적으로 수행합니다.
미리보기와 제외할 후보를 확인한 뒤 적용합니다. 사용하지 않는 객체의
제거나 중복 이름 수정은 참조 구조를 바꿀 수 있습니다. 현재 뷰에
안 보인다는 이유만으로 불필요한 객체라고 판단하지 않습니다.

## 선택, 원본 표시와 참조 이동 {#source-navigation}

Metrics, Profile, Topology는 Text, JSON, Table과 모델 선택을 공유합니다.
한 번 클릭하면 결과 탭을 바꾸지 않고 선택합니다. 호버는 대상과 관련
항목만 강조합니다. 탐색 대상의 더블클릭 또는 **Enter**는 선호하는
표현/뷰를 엽니다. 값 편집에 들어가는 것은 별도의 명시적 동작입니다.

| 동작 또는 기본 키 | 효과 |
| --- | --- |
| Definition / F12 | 참조된 정의를 입력 뷰에서 표시 |
| References / Shift+F12 | 알려진 참조 위치를 순서대로 이동 |
| Alt+Enter | 가능한 목적지가 여러 개일 때 선택 |
| Alt+Left / Alt+Right | 이전/다음 탐색 문맥 복원 |
| Escape | 먼저 임시 선택 창을 닫고, 그 외에는 선택 해제 |

키는 설정할 수 있으며 일반 편집 입력을 가로채지 않습니다. 값 편집과
충돌할 때는 화면의 동작 버튼을 사용합니다.

하나의 Zone은 기하와 부하 Profile처럼 여러 문맥에 등장할 수 있습니다.
여러 문맥에 보인다고 원본 객체가 복제된 것은 아닙니다. 목적지가 모호하면
선택 창을 사용합니다. 선택 추적은 필터, 뷰 모드와 로컬 범위를 보존하며
결과 탭을 자동으로 전환하지 않습니다. HVAC와 Simulation은 로컬 선택을
사용하므로 클릭이 원본 표시나 공통 선택 추적으로 이어지지 않습니다.

탐색은 분석된 문서 스냅샷을 사용합니다. 문서가 변경되었다면 현재 분석이
준비된 뒤 대상을 표시할 수 있습니다. Back/Forward는 뷰와 선택 문맥을
복원하며 편집을 되돌리지 않습니다. 스크롤, 호버, 이동/확대는 각각
별도의 탐색 기록을 만들지 않습니다.

## 문제 해석과 다음 확인 {#input-problems}

| 증상 | 다음 확인 |
| --- | --- |
| JSON/Table이 대기 중 | 현재 파싱을 기다리고 상태의 파싱 오류 확인 |
| 객체를 찾을 수 없음 | 필터 해제 후 정확한 유형/이름과 중복 이름 확인 |
| 참조의 가능한 정의가 여러 개 | 유형별 대상 규칙과 Diagnose의 중복 이름 확인 |
| 기하 객체의 폴리곤이 없음 | 지원 유형, 수치 좌표, 꼭짓점 수와 기초 표면 참조 확인 |
| 파싱 성공 후에도 값이 없음 | 해당 지표의 방법 확인: 파싱 성공만으로 계산 자료가 충분하지 않음 |
| 편집이 거부됨 | JSON 문법, 대상 필드/경로와 백엔드 오류 확인 |
| 변경이 결과에 나타나지 않음 | 계산 방식, 실제 Zone/Space 대상, 스케줄, 현재 분석과 승수 확인 |
