# Tools와 설정

Tools에는 Batch Metrics·Batch Simulation·Diagnose 작업 공간이 있습니다. Settings에서는 외관·상호작용·Profile 해석·엔진 실행 기본값을 관리합니다. 왼쪽 선택기로 도구를 고르며, 도구에서 선택한 파일과 메인 편집기의 모델은 구분합니다.

## Batch Metrics 사용 {#batch-metrics}

1. Batch Metrics를 선택하고 여러 입력 파일을 고릅니다.
2. 동일한 이름의 파일도 구분되도록 파일명과 표시명을 확인합니다.
3. 분석을 시작하고 완료 진행률을 확인합니다.
4. 필요한 지표 그룹으로 표를 필터링합니다.
5. 지표가 행인 방향과 파일이 행인 방향을 바꿉니다.
6. 두 파일 헤더를 선택해 기준 A와 비교 B를 지정합니다.
7. 현재 비교·표 표현을 내보냅니다.

EnergyPlus 실행이 아닌 정적 모델 분석입니다. 각 파일을 독립적으로 파싱합니다. 병렬 작업 수는 파일 수·감지한 CPU 수·최대 8개로 제한됩니다. 실패한 입력에 다른 파일의 값이 대신 채워지지 않습니다.

Batch Metrics는 유효 면적 기준을 사용합니다. 선택적 전체 Topology는 상세 자료를 추가하므로 계산량과 결과 크기를 늘립니다. 필요한 경우 활성화합니다.

## 차이값 해석 {#deltas}

호환되는 단위의 수치에는 다음 식을 사용합니다.

```text
절대 차이 = B - A
상대 차이(%) = 100 × (B - A) / A, 단 A ≠ 0
```

A가 100 m², B가 125 m²이면 +25 m²와 +25%입니다. 기준을 바꾸면 -25 m²와 -20%입니다. 백분율은 분모에 따라 달라집니다.

A가 0이면 절대 차이는 유효할 수 있지만 상대 차이는 제공하지 않습니다. 대시를 0%로 읽으면 안 됩니다. 문자 값은 가짜 백분율 대신 변경/동일로 표시합니다.

상태와 해석 조건도 비교해야 합니다. 특히 U값의 가용 범위가 다르거나 한쪽에만 범위 정보가 있으면 비교 불가로 표시합니다. 알려진 외피 일부가 더 작아진 상태에서 낮아진 U값을 전체 외피의 개선으로 해석할 수 없습니다.

표시 차이는 비교 표의 표시 수치를 바탕으로 계산합니다. 아주 작은 차이가 중요하면 상세 내보내기와 그 정밀도를 사용하며, 백분율 열에 추가 정밀도가 있다고 가정하지 않습니다.

## Batch Simulation {#batch-simulation}

Batch Simulation은 모델별로 별도 실행합니다. 입력·기상·목적을 선택하고 작업 수를 검토한 뒤 시작합니다. 각 행은 자체 상태·실행 입력·출력 디렉터리를 갖습니다.

엔진 완료 상태·출력 가용성·Energy Path 상세 상태는 서로 다른 단계를 설명합니다. 성공한 실행이라도 특정 차트에 필요한 관측값이 없을 수 있으며, 비교에 적합한 행만 선택할 수 있습니다.

행의 Energy Path 동작으로 보존된 실행 상세를 엽니다. 배치 비교와 행 상세는 Building/Annual/전체 서비스로 고정되며, 단일 Energy Path는 범위·기간 선택도 지원합니다. 서로 다른 기상·입력 버전·출력 기간·면적 기준을 설명 없이 하나의 성능 비교로 합치지 않습니다.

CSV는 표 분석에 적합합니다. XLSX·HTML Energy Path 보고서는 선택한 요약과 trace 상세를 포함할 수 있고, JSON은 구조화된 결과·내보내기 표현을 보존합니다. 범위·원본·내보내기 의미는 [에너지 경로](./energy-path.ko.md)를 참고합니다.

## 작업 수와 저장 공간 {#workers}

기본 시뮬레이션 작업 수는 감지한 논리 CPU 수로 계산합니다.

```text
작업 수 = max(1, ceil(CPU 수 × workerFraction))
maxWorkers > 0이면: 작업 수 = min(작업 수, maxWorkers)
```

기본 비율은 0.5입니다. 설정 정규화는 0.1–1.0 범위로 제한하며, 0 이하의 비율은 기본값으로 복원합니다. maxWorkers=0은 추가 설정 상한이 없다는 뜻입니다. 배치의 명시적 작업 수와 실제 작업량도 실행 동시성에 영향을 줍니다.

논리 CPU 12개·비율 0.5이면 초기 작업 수는 6개이고, maxWorkers=3이면 3개가 됩니다. 이는 동시성 설명이며 6배 가속을 보장하지 않습니다. 여러 EnergyPlus 프로세스가 메모리·디스크·CPU를 함께 사용합니다.

SQL과 요청한 출력에 충분한 저장 공간을 확보합니다. 높은 출력 빈도·많은 Surface·많은 시스템 Node는 작은 차트보다 훨씬 큰 원본 결과를 만들 수 있습니다. 재현이 필요하면 실행 모델·계획·ERR·SQL을 함께 보존합니다.

## Diagnose 사용 {#diagnose}

Diagnose는 현재 앱 입력 스냅샷 또는 별도로 고른 입력을 사용합니다. 진단 문제와 정리 후보는 관련된 보기지만, 경고 자체가 객체 제거를 뜻하지 않습니다.

1. 입력을 고르고 진단 문제를 검토합니다.
2. 왼쪽에서 정리 규칙을 선택합니다.
3. 오른쪽 후보의 체크박스와 객체 식별을 확인합니다.
4. 후보 필터를 사용하되 규칙 선택과 개별 후보 제외를 구분합니다.
5. 예상 정리 텍스트와 제거 개수를 확인합니다.
6. Apply selected로 작업 문서를 갱신·재분석하거나 Save cleaned copy로 새 파일을 만듭니다.
7. 중요한 참조와 모델 수치를 정리 전후로 비교합니다.

Save cleaned copy는 원래 입력 파일을 보존합니다. Apply는 작업 문서를 갱신하며, 이후 저장은 별도 작업입니다.

## 정리 규칙과 한계 {#cleanup-rules}

| 규칙 ID | 동작 | 검토 사항 |
| --- | --- | --- |
| remove_unused_schedules | 다른 필드에서 참조되지 않는 Schedule 제거 | 의도한 참조와 외부 작업 흐름 확인 |
| remove_unused_envelope_resources | 미참조 Material·WindowMaterial·Construction 제거 | 선택적 검토 규칙; 예비 자원일 수 있음 |
| remove_unused_curves_tables | 미참조 성능 Curve·Table 제거 | 선택적 검토 규칙; 커스텀·향후 시스템 확인 |
| remove_duplicate_output_variables | 동일 필드 서명의 Output·OutputControl:Table:Style 중 첫 객체 유지 | key·변수·빈도 의미 보존 |
| compact_formatting | 앱 formatter로 공백 형식 재작성 | 객체 제거와 구분 |
| remove_comments_only | 향후 기능용 예약 규칙 | 현재 사용 불가 |

사용 가능한 미사용 Schedule·중복 Output 규칙은 기본 선택될 수 있습니다. 다른 자원 제거는 검토를 거쳐 선택합니다. 미사용은 지원되는 참조 검색에서 사용을 찾지 못했다는 의미이며, 모든 확장·외부 프로세스에서 물리적으로 불필요하다는 증거는 아닙니다.

CLI Clean의 semantic 중복 이름 수정은 별도의 선택적 작업입니다. 중복 Output 요청 제거 또는 물리적 장비 두 개 병합과는 다릅니다.

## 외관과 상호작용 {#appearance}

외관 설정은 system/light/dark 테마·앱 언어·그래프 글자 크기·분석 탭 우선순위와 Topology의 배경·Zone·벽·지붕·개구부·선택 색상을 제공합니다. 색상 변경은 재료 특성이나 열 경계 분류를 바꾸지 않습니다.

키보드 설정은 기본 단축키를 대체합니다. 반응이 없으면 포커스와 문맥을 먼저 확인합니다. Topology의 한 글자 키는 해당 기능 안에서 적용되고, 편집 중에는 일반 입력을 유지해야 합니다. [기본 작업](./getting-started.ko.md#keyboard)을 참고합니다.

입력·결과 구분선은 분석값과 별도로 레이아웃을 저장합니다. 테마·페이지·구분선을 바꿔도 모델이나 시뮬레이션을 다시 생성하지 않습니다.

## Profile 설정 {#profile-settings}

활성 차원·표시/그룹 지표·수치 허용차·스케줄 비교 방식·시간 보기·축척을 선택합니다. 어떤 패턴을 비교하고 표시할지 결정하는 설정이며, 허용차 안에서 일치한다고 연간 시뮬레이션이 완전히 같은 것은 아닙니다.

Profile Apply 설정은 복제/수정·ZoneList 수정 또는 생성 허용·사본 이름 접미사·기존 이름 교체 정책을 제어합니다. 하나의 자원이 여러 Zone을 지원할 수 있으므로 미리보기와 대상 원본을 확인한 뒤 적용합니다.

가중치·스케줄 해석·지원 한계·표시 정규화와 원본 입력의 차이는 [지표와 Profile](./metrics.ko.md)을 참고합니다.

## 설정 저장과 복구 {#settings-storage}

백엔드가 로컬 앱 설정 영역에 정규화된 설정을 저장하며, 브라우저 저장소도 UI 상태를 캐시합니다. 설정 저장이 엔진·기상을 모델 파일에 포함하지는 않습니다.

엔진 검색에 실패하면 Simulation 설정의 설치 경로와 추가 기상 경로를 확인합니다. 예상과 다른 설정은 화면의 정규화된 값과 입력한 값을 비교합니다. 오래되거나 유효하지 않은 필드는 로드 시 보정될 수 있습니다.

출력 누락의 원인을 설정 초기화로 대신하지 않습니다. [문제 해결](./reference.ko.md)에서 증상별로 확인합니다.
