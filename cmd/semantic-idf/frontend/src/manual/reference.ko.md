# 단위·용어·문제 해결

수치·그래프·상태가 예상과 다르면 이 장을 사용합니다. 먼저 원본·단위·범위·기간·면적 기준·가용성을 확인합니다. 비슷한 표시명만 비교해서는 충분하지 않습니다.

## 해석 체크리스트 {#checklist}

중요한 값마다 다음을 확인합니다.

1. **식별:** 어떤 객체·출력 dictionary·실행·Zone/Building인가?
2. **물리량:** 에너지·전력·온도·유량·면적·비율 중 무엇인가?
3. **도메인:** 열부하·site 소비·발전·문맥 정보·형상 근거 중 무엇인가?
4. **시간:** 연간·월·순간 프레임·출력 구간 중 무엇인가?
5. **multiplier:** 대표 원본인가, 이미 모델 전체 관측인가?
6. **분모:** 물리/유효 면적·서비스 부하·완전한 소유자 집합·별도 예산 중 무엇인가?
7. **가용성:** 관측된 유한값·관측 0·부분 가용·부재 중 무엇인가?
8. **표현:** 반올림·샘플링·그룹·배분의 영향이 있는가?

Zone과 Building에서 각각 2 kWh/m²가 표시돼도 절대량이 같지는 않습니다. 각각 해당 면적을 곱해 총량을 비교합니다.

## 단위 {#units}

| 단위 | 물리량 | 흔한 오해 |
| --- | --- | --- |
| m² | 면·바닥 면적 | 대표 물리 면적과 multiplier를 반영한 유효 면적 혼합 |
| m³ | 체적 | 결측 체적을 임의 높이로 대체 |
| W | 전력·열 흐름률 | 프레임 수치를 연간 에너지로 해석 |
| kWh | 에너지 | 부하와 site 소비를 같은 도메인으로 해석 |
| kWh/m² | 면적당 에너지 | 선택 범위의 분모를 무시 |
| W/m² | 전력 밀도 | 설계 밀도를 시뮬레이션 평균 소비로 해석 |
| W/(m²·K) | U값 | 부분 Construction 가용성을 전체 외피 범위로 해석 |
| W/K | UA·열전달 conductance | 정적 UA를 관측 열 흐름률로 해석 |
| °C | 온도 | 독립 에너지 기여처럼 합산 |
| kg/s, m³/s | 질량·체적 유량 | 밀도·대응 관측 없이 직접 비교 |
| ACH, 1/h | 시간당 환기 횟수 | 총 유량과 체적당 비율 혼동 |
| people/m², m²/person | 사람 밀도·인당 면적 | 0 또는 미확인 인원을 역수로 변환 |
| m³/s/person | 인당 외기량 | 다른 또는 미확인 인원 분모 사용 |
| fraction, [-] | 무차원 값 | 모든 fraction을 확률·효율로 간주 |

기본 변환식입니다.

```text
1 kWh = 3,600,000 J
에너지(kWh) = Σ[전력(W) × 구간 초] / 3,600,000
UA(W/K) = U(W/(m²·K)) × 면적(m²)
ACH(1/h) = 체적 유량(m³/s) × 3,600 / 체적(m³)
```

Rate 적분에는 실제 출력 구간을 사용합니다. 특정 Time 행에 붙은 월 합계를 순간 Rate로 읽지 않습니다. 결측 구간에 한 달 전체를 조용히 부여하면 안 됩니다.

U×A는 정적 conductance입니다. UA×온도차로 열 흐름을 추정하려면 별도의 온도·물리 모델이 필요하며, 앱의 정적 UA가 관측 시뮬레이션 값으로 바뀌는 것은 아닙니다.

## 물리량과 유효량 {#multipliers}

대표 Zone은 여러 실제 인스턴스를 나타낼 수 있습니다. 지원되는 Zone/ZoneGroup 입력에서는 native Zone multiplier와 group/list multiplier를 조합해 유효 factor를 만듭니다.

대표 Zone 물리량에는 factor가 한 번 필요할 수 있습니다. 이미 모델 전체를 포함하는 component 에너지·meter에는 다시 곱하지 않습니다. 변수군마다 원본 권위가 다르므로 모든 SQL에 Zone factor를 곱하면 안 됩니다.

factor 6·물리 면적 24 m²이면 유효 면적은 144 m²입니다. 대표 Zone 에너지 10 kWh는 해당 관측이 배수를 요구할 때 60 kWh가 됩니다. 60/144와 10/24는 모두 약 0.4167 kWh/m²입니다. 에너지에 배수를 두 번 곱하면 강도가 잘못됩니다.

Surface·Floor Area·열 경계 pair 면적에는 각각 기준이 있습니다. 한 multiplier 규칙을 모든 지표에 옮기지 않고 기능의 면적 기준을 확인합니다.

## 0·결측·부분 가용 {#knownness}

| 상태 | 의미 | 해석 방법 |
| --- | --- | --- |
| 관측 양수/음수 | 유효 원본에 유한한 물리량 존재 | 부호·단위·역할 보존 |
| 관측 0 | 완전하고 유효한 관측으로 0 확인 | 가용성을 유지; 비율은 별도 분모 확인 |
| 결측/부재 | 필요한 원본·값·소유 근거 없음 | 0으로 대체하지 않음 |
| 부분 가용 | 지원 입력·범위 일부만 알려짐 | 범위와 제외·미해결 원본 확인 |
| 적용 불가 | 분모·서비스가 의미 없는 관계 | 효율을 임의 생성하지 않음 |
| 표시 반올림 0 | 작은 비제로 값이 표시에서 사라짐 | 원본·내보낸 값 확인 후 정확한 0 판단 |

상태는 기능별 계약입니다. Metrics 상태·실행 상태·Energy Path 품질을 하나의 공통 점수로 바꾸지 않습니다.

dictionary 이름이 존재한다고 관측이 완전한 것은 아닙니다. 요청한 출력도 누락될 수 있고, 요청하지 않은 출력의 부재에는 이유가 있을 수 있습니다. SQL NULL과 행 부재는 관측 0이 아닙니다.

## 정밀도·그룹·샘플링 {#precision}

Energy Path는 일반적으로 kWh/m²를 소수점 두 자리로 표시합니다. 100 m²에서 양수 0.004 kWh는 0.00004 kWh/m²이므로 0.00으로 보일 수 있습니다. 원본 에너지는 여전히 양수입니다.

집계·배분에는 별도의 정밀도 계약이 있습니다. 월 배분을 완료한 뒤 Annual을 합산합니다. 연간 총량을 별도로 배분해서 Zone별 나머지가 같을 것이라고 기대하지 않습니다. 작은 반올림 예산에는 결정적인 나머지 처리가 필요합니다.

Other 그룹은 원본 식별·수치를 바꾸지 않고 표시 구성원을 바꿉니다. 중요한 분류는 그룹 규칙에 따라 유지하며, 과거 고정 Node 개수 선호만으로 숨기지 않습니다.

샘플링된 overview·frame은 화면 해석 성능을 높이지만 전체 에너지 집계·완전한 Hourly trace의 대체물이 아닙니다. 같은 실행이라도 두 그래프의 샘플 시각이 다를 수 있으므로 원본과 동일 시각 정렬 규칙을 확인합니다.

## 적용 범위와 한계 {#support-limits}

분석기는 지원되는 객체군과 근거 패턴을 처리합니다. EnergyPlus에서 실행 성공한 객체도 앱의 정적 그래프·소유 규칙·Energy Path 변환에서 인식되지 않을 수 있습니다.

전체 합성/오프라인 검사·엔진 성공·독립 물리/수치 검토는 각각 다른 질문에 답합니다. 매뉴얼은 지원되는 해석을 설명하며 모든 장비·기후·설계를 승인하지 않습니다.

모델 확장·비교 시 미해결 상태·원래 출력·독립 근거를 보존합니다. 진단에 유용한 문맥은 가산 배분할 수 없어도 유지해야 합니다.
